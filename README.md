# 💰 Учёт личных трат

Семестровый учебный проект по веб-разработке на Go: приложение для учёта личных расходов.
Сервер на стандартной библиотеке `net/http`, HTML-страницы через `html/template`, хранение данных в SQLite.

**Статус:** выполнены этапы 1–3.

| Этап | Тема                        | Результат                                   |
|------|-----------------------------|---------------------------------------------|
| 1    | Основы Go и HTTP            | Сервер с маршрутами `/`, `/about`, `/ping`  |
| 2    | Шаблоны и первый интерфейс  | Список трат и форма добавления (в памяти)   |
| 3    | База данных SQLite          | CRUD трат через репозиторий                 |

## Технологии

- Go 1.22 или новее (нужна для маршрутов вида `GET /add`)
- `net/http`, `html/template`, `database/sql`
- SQLite, драйвер `modernc.org/sqlite` (чистый Go, без CGO)
- HTML и CSS без фреймворков

## Запуск

Команды выполняются **из корня проекта** (где лежит `go.mod`): пути к шаблонам, статике и базе заданы относительно него.

```bash
go mod tidy
go run ./cmd/server
```

Откройте в браузере: <http://localhost:8080>

Чтобы начать с чистой базы, остановите сервер и удалите `expenses.db`. При следующем запуске таблица создастся заново.

## Этап 1. Основы Go и HTTP-сервера

Простой HTTP-сервер без сторонних зависимостей (файл `Atap1.go`, запуск `go run .`).

| Метод  | Путь     | Ответ                        |
|--------|----------|------------------------------|
| GET    | `/`      | 200, приветственный текст    |
| GET    | `/about` | 200, описание проекта        |
| GET    | `/ping`  | 200, `pong`                  |
| другие | `/ping`  | 405 Method Not Allowed       |
| любой  | прочие   | 404 Not Found                |

Проверка через curl:

```bash
curl -i http://localhost:8080/ping
curl -i -X POST http://localhost:8080/ping   # 405
```

## Этап 2. Шаблоны и первый интерфейс

- Разделение проекта на слои: `cmd`, `internal/handlers`, `internal/models`, `web`.
- Структура `Expense`, список трат выводится таблицей через `{{range}}`.
- Общий layout для всех страниц.
- Форма добавления траты и паттерн Post/Redirect/Get: после `POST /add` сервер отвечает `303 See Other`, поэтому обновление страницы не отправляет форму повторно.
- На этом этапе данные хранились в срезе в памяти и терялись при перезапуске.

## Этап 3. База данных SQLite и репозиторий

- Данные хранятся в файле `expenses.db` и сохраняются между перезапусками.
- Весь SQL находится в `ExpenseRepository` (`Create`, `GetAll`, `GetByID`, `Update`, `Delete`), обработчики SQL не содержат.
- Запросы используют placeholder `?`, что защищает от SQL-инъекций.
- Список сортируется от новых трат к старым, удаление выполняется с подтверждением.

Таблица `expenses`:

| Поле          | Тип     | Описание                      |
|---------------|---------|-------------------------------|
| `id`          | INTEGER | первичный ключ, автоинкремент |
| `amount`      | REAL    | сумма                         |
| `description` | TEXT    | описание                      |
| `date`        | TEXT    | дата в формате `YYYY-MM-DD`   |

Схема описана в `migrations/001_create_expenses.sql`. Таблица создаётся при старте сервера запросом `CREATE TABLE IF NOT EXISTS`.

## Маршруты приложения (этап 3)

| Метод | Путь          | Описание                                 |
|-------|---------------|------------------------------------------|
| GET   | `/`           | Список трат                              |
| GET   | `/add`        | Форма добавления                         |
| POST  | `/add`        | Сохранение новой траты, redirect на `/`  |
| GET   | `/edit?id=N`  | Форма редактирования траты N             |
| POST  | `/edit`       | Сохранение изменений (id в скрытом поле) |
| POST  | `/delete`     | Удаление траты (id в форме)              |
| GET   | `/static/...` | Статические файлы (CSS)                  |
